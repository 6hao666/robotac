# 故障排查

## 排查原则

故障定位前须确认当前验证等级和安全状态，并按照设备至数据、上游至下游的顺序逐层检查。
严禁通过关闭门禁、伪造 TF、放宽权限或改为无人监管控制的方式规避故障。

通用顺序：

1. 记录 Git SHA、配置和现象。
2. 确认没有活动飞行任务，飞机未解锁且处于安全状态。
3. 检查设备和权限。
4. 检查节点、话题类型、频率、时间戳和 frame_id。
5. 检查 TF、参数、消费者和状态话题中的明确拒绝原因。
6. 每轮仅修改一项可能原因，并从对应验证等级重新验证。

## 串口权限错误

**现象：** MAVROS 或舵机节点提示无法打开 `<串口设备>`、权限不足或设备不存在。

**检查：**

```bash
ls -l <串口设备>
id
udevadm info --attribute-walk --name=<串口设备>
```

确认设备为目标飞控或控制器，udev 规则的厂商、产品和序列属性匹配，当前用户在
`dialout` 组且已经重新登录。禁止使用全局可写权限。设备名变化时须修正稳定别名，不得在
多个 launch 中分别硬编码临时路径。

## LiDAR 数据缺失

**现象：** Livox 节点存在，但 `/livox/lidar` 或 `/livox/imu` 无消息。

**检查：**

```bash
ip address
ip route
rostopic type /livox/lidar
rostopic hz /livox/lidar
rostopic hz /livox/imu
```

核对 `config/lidar/mid360s.json` 中 `<机载网卡地址>` 与 `<雷达地址>`、网卡子网、端口和
雷达实际设置。若日志提示发现未在配置中定义的雷达，通常是地址不匹配。修正配置后须回到
只读等级，不得将丢包或零频率问题带入 FAST-LIO 验证。

## MAVROS 未连接

**现象：** `/mavros/state.connected` 为假，或 MAVROS 反复重连。

**检查：**

- `<飞控串口设备>` 是否稳定存在、权限正确、没有被其他进程占用。
- `fcu_url` 的波特率是否与 PX4 端口一致。
- 飞控供电、线缆和端口配置是否正确。
- `config/mavros/px4_pluginlists.yaml` 是否为项目版本。
- 确认 ROS master 和 MAVROS 节点已稳定运行。

不得通过调用模式或解锁服务测试连接状态。连接问题仅可使用被动遥测确认。

## FAST-LIO 里程计缺失

**现象：** `/livox/*` 有数据，但 `/Odometry` 无频率或状态异常。

**检查：**

```bash
rostopic hz /livox/lidar
rostopic hz /livox/imu
rostopic hz /Odometry
rostopic echo -n 1 /Odometry/header
rosrun tf tf_echo camera_init body
```

依次检查消息类型、时间同步、`config/fastlio/mid360s.yaml` 的话题与雷达类型、外参格式、
IMU 数据和启动日志。`/Odometry` 存在后仍须检查频率、时间戳、方向和漂移，不得仅以
话题存在判定验证通过。

## TF 缺失或方向错误

**现象：** AprilTag 无法转到目标帧、视觉状态提示 frame 不匹配，或手动运动方向相反。

**检查：**

- 须先确定缺失的父子关系，原因未确认前不得添加静态 TF。
- 核对 `camera_init -> body`、外部视觉输出帧、MAVROS 本地帧和相机光学帧。
- 使用 `fastlio_frame_alignment_observer.launch` 在 MAVROS 视觉输出关闭时记录各轴运动。
- 核对 `camera_extrinsics.launch` 是否仍为零占位。

TF 名称连通不代表数值正确。错误静态变换可能将问题转移至飞行控制层并扩大风险。

## AprilTag 检测缺失

**现象：** 相机有图像，但 `/tag_detections` 为空或不稳定。

**检查：**

- 图像话题、相机信息和时间戳是否同步。
- 分辨率是否与 `config/camera/*.yaml` 标定一致。
- 曝光、运动模糊、照明、反光、视角和遮挡。
- `config/apriltag/settings.yaml` 的 Tag 家族和检测参数。
- `config/apriltag/tags.yaml` 的编号和边长是否对应实体。
- 相机外参和光学帧方向是否正确。

错误编号或错误尺寸可能产生数值表面合理但尺度错误的位姿，须同时核对图像和配置。

## 舵机无响应

**现象：** 节点启动失败、状态返回写入失败，或串口成功但机构不动作。

**检查：**

- `<舵机串口设备>`、`dialout` 权限和 udev 规则。
- 波特率、通道、PWM 频率与控制器协议。
- 供电、地线、舵机负载、机械限位和卡滞。
- `/robotac_servo/status` 的 `success` 与序号。
- 开关角度是否在机构安全范围内。

状态话题仅确认串口写入，不确认实际角度。机械不动作时应断开飞行任务，在独立地面工位
排查，禁止通过重复发送投放命令强制打开机构。

## FAST-LIO 外部视觉健康检查失败

**现象：** `/robotac/fastlio_vision/healthy` 为假，或 `status` 报告年龄、频率、帧、速度、
航向跳变或半径超限。

应按状态文本定位具体阈值，核对输入时间戳和帧，再检查对应 `config/fastlio/*.yaml`。阈值用于
拦截异常，根因未确认前不得直接放宽。阈值调整必须以测量结果证明正常运动超出原范围为依据，
并在调整后重新执行仿真。

## 安全门禁拒绝启动

**现象：** launch 的硬件检查退出，或任务 `start` 返回失败。

检查：

1. `config/deployment.yaml` 中的未确认项。
2. 控制、自动模式、解锁、降落、投放是否按批准方案分别启用。
3. MAVROS 是否连接、未解锁状态和落地状态是否符合当前阶段。
4. 本地位置、外部视觉、时间同步和估计器状态是否新鲜健康。
5. `/mavros` 是否真实订阅视觉输出和设定点。
6. 舵机连接与回执是否满足所选任务要求。
7. 路线帧、范围和 `route_manifest` 是否有效。

门禁拒绝通常由上游条件不满足引起，须依据返回原因补齐证据。禁止通过删除代码检查、复制
仿真门禁到实机或批量修改布尔值规避门禁。

## 任务中止或超时

须保存 `/robotac/*/status`、MAVROS 状态、定位、消费者和系统日志，并按现场预案确认飞机安全。
常见原因包括数据断流、消费者消失、状态超时、航点无法达到、Tag 扫描超时、舵机回执失败
和总时限到达。复位前必须定位原因，并从对应验证等级重新开始。

## 提交故障记录

故障单至少包含：

- Git SHA、脱敏配置和验证等级。
- 预期、实际、首次错误时间和稳定复现步骤。
- 相关状态话题、频率、时间戳、TF 和日志片段。
- 已排除项、改动项、恢复结果和遗留风险。

故障记录不得包含凭据、真实网络布局、飞控 UID、个人绝对路径或未经脱敏的现场数据。
