## 2. 比赛背景与考查目标

C 组为独立封闭场地内的指定无人机自主任务。参赛队使用同一架登记无人机，在一次完整飞行中依次完成自主起飞、侧向绕障、固定目标视觉识别与自主对准、模拟货物自主释放、返程再次绕障和自主降落。

赛事不仅考查单项算法，还考查指定平台上的软件部署、硬件接口适配、系统联调、任务闭环、安全机制、测试证据和现场实飞结果。规则允许 Gazebo、SITL、HITL 或直接真机调试，不强制使用 Isaac Sim。

### 2.1 总分构成

| 模块 | 阶段 | 分值 |
| --- | --- | ---: |
| 真机系统搭建与调试 | 赛前线上预审 | 22 |

真机任务、答辩和预审材料是一条连续证据链：代码必须能运行，任务日志必须能解释本次飞行，测试记录必须能说明问题、原因、处理和验证结果。

## 3. 场地、目标与器材硬约束

### 3.1 场地几何

| 项目 | 规则值 |
| --- | --- |
| 有效飞行区 | `4.00 m × 5.00 m` |
| 起降台圆心 | 场地坐标 `(2.00, 0.80)` |
| 固定投放台圆心 | 场地坐标 `(2.00, 4.20)` |
| 两张圆桌 | 高 `0.75 m`，桌面直径 `0.80 m` |
| 固定障碍物 | `2.10 m × 0.15 m × 2.00 m`，横向位于场地中部 |
| 障碍物两侧物理净宽 | 各 `0.95 m` |
| 场地评审区净高 | 暂定 `3.00 m` |

去程和返程都必须从障碍物左端或右端绕过，可以选择相同侧或不同侧。无人机水平轨迹穿过障碍物地面投影范围会被判为顶部越障，规则明确禁止。

场地边界以标线内侧边缘为判定线；机体外轮廓投影越过边缘即为越界。这一点与仅检查无人机中心点是否越界不同。

### 3.2 圆桌得分区与 AprilTag

| 对象 | 得分区 | 视觉标志 |
| --- | --- | --- |
| 起降台 | 直径 `0.60 m` 内为良好区，`0.60-0.80 m` 圆环为有效区 | Tag36h11，ID 0，黑色编码区边长 `150 mm` |
| 固定投放台 | 直径 `0.40 m` 内为精准区，`0.40-0.60 m` 为良好区，`0.60-0.80 m` 为有效区 | 与起降台相同的 Tag36h11 ID 0 |

两张桌使用相同 ID，因此程序不能仅靠 Tag ID 判断当前看到哪张桌。当前任务的区分依据必须来自任务阶段、场地位置和坐标变换。

### 3.3 指定平台与模拟货物

- 参赛队须携带组委会指定型号的 C 组无人机和官方投放机构，两次正式飞行使用同一架登记无人机。
- 可以针对本机做标定、参数适配和软件调试，但不得擅自更换机架、动力系统、飞控核心硬件或官方投放机构。
- 模拟货物质量 `100-110 g`，外径 `52 mm`，盘面轮廓直径 `49 mm`，盘体厚 `8 mm`，总高 `25 mm`，挂载孔直径 `4 mm`。

飞书资料描述的比赛款平台现状如下：

- 基于 Sunray-150 三维激光雷达款改装；
- 机载计算机为 Jetson Orin Nano 配达妙载板，上电自动开机；
- 飞控为微空科技 NxtPX4 v2；
- 遥控器使用 ERLS 协议，建议先开遥控器再给无人机上电；
- 舵机通过 USB-C 接入 Orin Nano，首次使用前必须按仓库标定文档完成投放机构标定。

### 3.4 飞控固件与参数依赖

飞书页面提供 PX4 v1.15.2 的 400 MHz 与 360 MHz 两种 NxtPX4 固件，说明正常情况使用 400 MHz，出现过热重启风险时才考虑 360 MHz；同时提供 `RoboTac_Final.params`，要求通过 QGroundControl 写入并重启飞控。

页面把手动定位飞行与激光雷达里程计 Offboard 飞行区分为两套高度/定位数据源。对当前 mission 最相关的建议值包括：

| 参数 | 页面建议 | 对 mission 的意义 |
| --- | --- | --- |
| `EKF2_GPS_CTRL` | `0` | 室内禁用 GNSS 融合 |
| `EKF2_EV_CTRL` | `11` | 融合外部视觉水平位置、垂直位置和 yaw |
| `EKF2_HGT_REF` | `3` | 以 MAVLink 102 外部视觉高度为长期高度参考 |
| `EKF2_RNG_CTRL` / `EKF2_TERR_MASK` | `0` / `0` | 避免测距与地形估计同外部视觉高度互相拉扯 |
| `MPC_ALT_MODE` / `EKF2_OF_CTRL` | `0` / `0` | 使用本地原点高度控制，并禁用光流融合 |
| `COM_ARM_WO_GPS` | `1` | 允许无 GPS 条件下在其他安全检查通过后解锁 |
| `COM_RC_IN_MODE` / `COM_RC_OVERRIDE` | `0` / `3` | 保留实体遥控器，并允许在 Offboard 中摇杆接管 |

这些值是飞书页面的配置建议，不是本次对登记飞机的读取结果。正式飞行前仍须在目标飞控上逐项核对实际值、重启生效情况、estimator 状态、遥控器输入、急停和接管行为。

## 4. 现场流程、计时与成绩口径

### 4.1 正式飞行流程

1. 从起降台自主解锁、起飞并进入稳定悬停；
2. 从固定障碍物任一侧完成去程绕行；
3. 识别固定投放台目标，依据识别结果自主对准并稳定悬停；
4. 程序自主触发投放机构，使模拟货物完全脱离；
5. 再次侧向绕过固定障碍物，返回起降台并自主降落；
6. 裁判记录本次完整飞行的完成情况和得分。

### 4.2 计时和飞行次数

- 每队最多两次正式飞行；
- 两次飞行和中间复位、重新放置、重新挂载共用连续 `6 分钟`；
- 裁判发出开始指令即开始计时，中间不暂停、不重新开始；
- 每次飞行只允许一次任务启动操作；
- 两次飞行必须使用计时开始时已经部署的同一套程序；
- 达到 6 分钟后停止真机任务计分；
- 最终采用两次飞行中较高的一次完整成绩，不能拼接两次飞行的分项成绩。

## 5. C1-C5 判分条件

| 项目 | 主要判定 | 分值 |
| --- | --- | ---: |
| C1 自主起飞与状态建立 | 自主解锁起飞，使无人机几何中心距场地地面达到 `1.00-2.00 m`；在范围内稳定不少于 `3 s` | 5 |
| C2 自主飞行与固定障碍绕行 | 自主接近障碍、从任一侧无碰撞且不越界地绕过、进入投放台附近 | 8 |
| C3 视觉识别与自主对准 | 机载视觉识别目标并输出可核验结果；依据识别自主修正；中心投影进入桌面外边界并稳定不少于 `3 s` | 8 |
| C4 自主释放与落点 | 程序自主触发且货物完全脱离最高得 3 分；落点按投放台精准/良好/有效区再得 6/4/2 分 | 9 |
| C5 自主返航与降落 | 释放后再次侧向绕障；无人机几何中心投影落入起降台良好区得 3 分、有效区得 1 分 | 5 |

C3 的可核验结果至少应包含目标识别状态，以及目标位置或中心偏差。只依靠预设坐标抵达投放台不能替代视觉识别和自主对准得分。

C4 的串口或服务调用成功不等于货物已经完全脱离。C5 的降落判定使用无人机几何中心投影，不要求全部机体轮廓位于桌面内；但飞行边界判定使用机体外轮廓。

## 6. 安全、中断与违规

- 每队必须指定安全操作员；无人机出现失控趋势、冲向障碍物或边界、异常快速下降时必须立即接管。
- 裁判也可以要求接管或急停。人工接管后本次飞行立即停止计分，接管前已经自主完成的项目保留。
- 越界、严重撞击、拒绝安全指令等会立即终止本次飞行。
- 自备无人机、电池、程序或设备故障原则上不属于可补时原因。
- 预录画面、伪造日志、遮挡或修改官方视觉标志、绕过接管机制等属于严重违规。

飞书给出的 Offboard 接管参数建议包括 `COM_RC_IN_MODE=0`、`COM_RC_OVERRIDE=3`、`COM_RC_STICK_OV=30`，并单列 `RC_KILLSWITCH_TH` 与 `COM_KILL_DISARM`。这些属于目标飞控的现场参数，不由 `robotac_mission` 自动设置；比赛前必须在登记飞机上读取并实测，而不能只相信参数文件或说明页。

## 9. 当前状态机结构

### 9.1 状态流

```text
BOOT
  -> WAIT_READY
  -> WAIT_START
  -> TAKEOFF
  -> TRANSIT
  -> SEARCH_TAG
  -> ALIGN_TAG
  -> RELEASE
  -> RETURN
  -> LAND
  -> COMPLETE

任一飞行态 --stop/健康门/阶段超时--> ABORT_LAND
ABORT_LAND --确认落地或人工接管--> COMPLETE
BOOT --参数无效--> ERROR --reset/重读参数--> BOOT
```

状态机核心只维护合法转移、`active`、首个结果根因和最近 200 条转移记录。飞行动作由 20 Hz `FlightDriver` 驱动。节点使用进程级 `RLock` 串行化服务、订阅状态评估和定时推进。

### 9.2 启动前安全门

`WAIT_READY` 进入 `WAIT_START` 前要求：

- FCU 已连接、飞机未解锁；
- `landed_state` 表示在地面；
- 本地位姿新鲜且数值有限；
- estimator 的姿态、水平相对位置和垂直绝对位置标志有效；
- timesync 往返延迟合格且话题新鲜；
- `/vision_pose_bridge/healthy=true`、`state=OK`，且两个话题持续更新。

`start` 服务会重新同步评估一次安全门，避免依赖最多 0.2 秒前的定时器结果。启动前不检查场地边界，因为 FAST-LIO 原点尚未映射到场地坐标。

### 9.3 各飞行阶段的代码行为

| 状态 | 当前行为 | 完成条件 | 失败路径 |
| --- | --- | --- | --- |
| TAKEOFF | 预发位置目标，切 OFFBOARD，解锁，以启动位姿为基准相对爬升 | 距离目标不超过 `0.15 m` 并保持 `3 s` | 服务失败或 `20 s` 超时后中止 |
| TRANSIT | 顺序跟随 4 个去程航点 | 每点到达并保持 `1 s`，完成全部航点 | `30 s` 超时或健康门失败 |
| SEARCH_TAG | 保持投放台名义点，筛选 ID 0，变换到 `map` 并积累稳定样本 | 稳定 Tag 位于投放台圆心 `1.0 m` 搜索半径内 | `30 s` 超时 |
| ALIGN_TAG | 依据 Tag 与飞机位置差修正水平目标，高度保持任务点高度 | 水平误差不超过 `0.15 m` 并保持 `3 s` | Tag/位姿失效或 `20 s` 超时 |
| RELEASE | 可选调用舵机服务，然后继续保持任务点 | 保持 `1 s` | 舵机失败或 `10 s` 超时 |
| RETURN | 顺序跟随 4 个返程航点，再到返回点 | 全部航点完成 | `30 s` 超时或健康门失败 |
| LAND | 请求 `AUTO.LAND` | PX4 报告落地 | 等待 `30 s` 后中止 |

### 9.4 运行中健康门

当前飞行健康检查包含：

- FCU 连接状态；
- 本地位姿是否存在、是否超过 `0.5 s`、是否跳变；
- estimator 当前标志；
- OFFBOARD/AUTO.LAND 模式；
- 视觉状态值；
- timesync 与 `vision_healthy` 的新鲜度和软去抖；
- 通过 `map_to_field` 后的中心点场地边界检查；
- TAKEOFF/LAND 以外的飞行阶段意外上锁检查。

所有飞行阶段失败统一进入 `ABORT_LAND`。节点只尝试一次切换 `AUTO.LAND`；落地状态确认后进入 `COMPLETE`。操作员也可调用 `/robotac_mission/manual_takeover` 结束中止态。

## 10. 当前默认配置的实际含义

下面是仓库当前 [mission.yaml](../src/robotac_mission/config/mission.yaml) 的实际值，不采用 README 中的“默认”表述替代：

| 配置 | 当前值 | 实际影响 |
| --- | --- | --- |
| `mission.dry_run` | `false` | 接受 start 后会真实发 MAVROS 设定点并调用模式/解锁服务 |
| `mission.flight_enabled` | `true` | start 会进入 TAKEOFF，而不是停留在骨架状态 |
| `payload.enable` | `false` | RELEASE 状态跳过舵机调用，当前程序不会完成真实 C4 释放 |
| `limits.max_speed` | `0.2 m/s` | 普通场地航点按 `max_speed / rate_hz` 限制每个控制周期的目标步长；`is_map=true` 的起飞目标不经过该限幅 |
| `waypoints.takeoff` | `[2.0, 0.8, 1.0]` | z 在 TAKEOFF 中被当作相对当前 FC 位姿的爬升量 |
| 去程/返程绕障航点 | 全部 `x=2.0` | 当前沿场地中线穿越障碍物投影，不是合规侧向绕障路线 |
| `total_window` | `360 s` | 仅 start 时用于判断是否还有时间启动 |
| `flight_budget` | `150 s` | 第二次及后续 start 的剩余时间门槛 |
| `takeoff_hold` / `align_hold` | `3 s` / `3 s` | 对应 C1/C3 规则硬要求 |
| Tag | `tag36h11`、ID 0、`0.15 m` | 与规则一致；实际识别族和尺寸由 AprilTag launch 配置 |

配置校验目前只确认航点在场地长方体内，并未验证航段与障碍物是否相交，也未使用 `obstacle.no_overfly` 自动拒绝违规路线。

## 11. 规则与当前代码的逐项映射

| 规则项 | 当前代码覆盖 | 当前缺口或依赖 |
| --- | --- | --- |
| C1 自主起飞、1-2 m、稳定 3 s | 有 TAKEOFF、OFFBOARD、解锁、相对爬升和 3 s 保持 | 没有独立测量“几何中心距场地地面”；当前 z 原点来自桌上启动位姿，规则高度与控制高度需实测换算 |
| C2 去程侧向绕障 | 有 TRANSIT 和四航点路由框架 | 当前默认航点穿过障碍中线；无航段碰撞、机体外形、净空或顶部越障校验 |
| C3 视觉识别、自主对准、日志、3 s | 有 Tag ID 过滤、TF 变换、稳定样本、自主修正和 3 s 保持 | 依赖未在本次验证的相机内参、外参和 TF；mission 没有专门发布识别状态/目标偏差，比赛可核验日志链不完整 |
| C4 自主释放与完全脱离 | 有 RELEASE 状态和舵机服务封装 | 当前 `payload.enable=false`，不会释放；服务成功也没有货物脱离传感或结果确认 |
| C5 返程绕障与桌面降落 | 有 RETURN、返回点和 AUTO.LAND | 返程默认路线同样穿过障碍；降落仅依赖固定坐标，没有桌面视觉复核或得分区估计 |
| 两次飞行、连续 6 分钟 | 保存首次 start 时间，后续 start 检查剩余预算 | 没有“最多两次”计数；飞行进行中不检查 6 分钟截止；状态机允许时间足够时继续 reset/start |
| 人工接管后停止计分 | 有 stop、ABORT_LAND 和 manual_takeover 服务 | 遥控器接管导致 OFFBOARD 丢失后，程序会进入 ABORT_LAND 并尝试 AUTO.LAND，可能与人工接管意图竞争，需重点审计 |
| 边界使用机体外轮廓 | 有中心点场地范围检查和 `0.1 m` 容差 | 未考虑机体/保护圈半径，不能直接证明规则意义上的未越界 |
| 使用同一程序、保留运行证据 | 有状态、原因、结果和 rosbag 工具 | 运行脚本未记录 `/robotac_mission/target` 与舵机状态；mission 自身未发布 Tag 偏差/识别状态 |

## 12. 已确认的文档与测试漂移

这些是当前基线中的一致性问题，不等同于最终缺陷定级：

1. [robotac_mission/README.md](../src/robotac_mission/README.md) 多处称 `flight_enabled=false`、`dry_run=true` 为默认值，但当前 YAML 实际为 `true`、`false`。
2. [mission_sim.test](../src/robotac_mission/launch/mission_sim.test) 直接加载当前 YAML，而 [mission_sim_test.py](../src/robotac_mission/test/mission_sim_test.py) 仍断言 start 停留 `WAIT_START` 且不发送设定点；与当前配置不一致。
3. `package.xml` 的描述仍称包为“骨架轮，仅含预启动状态”；`competition_mission.launch` 只强调启动 launch 后不会自动飞行，却没有提示当前默认配置下手动 start 会进入真实控制，文档语义容易误导。
4. 根 README 的工作空间组成未列出 `robotac_mission`；`docs/05-competition-examples.md` 仍说比赛路线、飞行联动和返程路线不在 Repo 中，落后于现有状态机包。
5. mission README 记录“68 个纯单测”，当前五个 mission 纯测试文件实际声明 81 个测试；本次环境执行了其中 65 个，16 个配置测试因缺少 PyYAML 未加载。
6. `timing.stage_timeout.land` 被配置和校验，但 LAND 实际使用 `timing.land_confirm`；该字段当前为未消费配置。
7. `obstacle.no_overfly`、`obstacle.cross_gap`、`tag.family`、`tag.black_size_m`、`frames.body_frame` 和节点参数 `camera_frame` 主要停留在配置/校验或注释层，未直接参与 mission 运行判定。

## 13. 状态机全面审计的优先入口

### 13.1 必须先处理的比赛阻断项

1. 合规去程与返程路线：航段必须从 0.95 m 侧隙通过，并计入机体尺寸、定位误差和安全余量。
2. C4 真正启用条件：舵机节点、稳定设备别名、标定值、挂载状态、服务响应和完全脱离证据。
3. 6 分钟与两次飞行：建立明确的计时器、飞行次数和飞行中截止策略。
4. 人工接管仲裁：区分软件故障降落、摇杆接管和急停，避免程序在接管后重新请求自动模式。
5. 坐标基准：证明 FAST-LIO/MAVROS `map` 的 xy 方向与场地坐标一致；当前 `Coordinates` 只有平移，没有把 `home_yaw` 用于平面旋转。
6. 高度口径：区分桌面高度、起飞时 FC 原点、飞机几何中心和规则中的“距场地地面高度”。

### 13.2 控制与故障路径审计

- 枚举每个状态的进入条件、保持不变量、完成条件、超时和外部副作用；
- 对 start/stop/reset/manual_takeover 与 20 Hz tick 的并发顺序做事件表；
- 核对飞行中 FCU、estimator、vision state、extended state 的数据年龄，而不只检查最后值；
- 核对 MAVROS 设定点订阅中断、模式切换失败、AUTO.LAND 失败、意外上锁和飞控断连；
- 检查 SEARCH/ALIGN 对同一 Tag 消息、Tag 消失、TF 失败、错误外参和错误桌面匹配的行为；
- 检查舵机调用的超时、幂等、重试、服务卡死和机械未脱离；
- 检查 `COMPLETE`、首个根因、得分阶段和实际落地状态是否会被错误合并。

### 13.3 测试矩阵

需要补齐至少四层验证：

1. 纯 Python：状态转移、时间窗口、飞行次数、坐标旋转、航段/障碍几何、所有配置消费；
2. ROS 假节点：完整 TAKEOFF 到 LAND、Tag/TF/舵机故障、遥控器接管、断连和话题冻结；
3. SITL/HITL：OFFBOARD、模式切换、设定点流、AUTO.LAND 和 6 分钟截止；
4. 真机分阶段：拆桨地面、低风险悬停、单侧绕障、视觉对准、空载释放、带载投放、返航降落。
