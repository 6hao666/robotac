# 安全与验证

## 核心原则

Robotac 采用五级验证流程。各等级仅验证其规定范围，低等级验证结果不得替代高等级证据。
进入下一等级前，必须完成本级记录、遗留风险评审和负责人批准。

## 五级流程

### 第 1 级：离线检查

目标是证明源码、配置引用和安全契约自洽，不接设备、不启动 ROS、不访问飞机。

```bash
./scripts/check_flight_contract.py
./scripts/verify_workspace.sh
./scripts/flight_test_ladder.sh
git diff --check
```

检查内容：文件完整性、launch 默认值、部署门禁、接口名称、路线范围、脚本语法和可用的
硬件隔离测试。检查失败时不得进入下一验证等级，须在本级完成修复和复验。

### 第 2 级：硬件隔离仿真

目标是证明状态机、坐标转换、航点、投放指令和故障分支按预期运行。仿真必须使用独立
ROS master 和 `config/deployment_sim.yaml`，不得连接飞控、雷达、相机或舵机设备。

应覆盖：

- 正常任务完成路径。
- 视觉数据断流、时间戳和跳变异常。
- MAVROS 或设定点消费者丢失。
- Offboard、解锁、降落或舵机回执失败。
- 中止、超时和复位路径。
- 路线清单与实际目标一致。

### 第 3 级：只读实机观察

目标是确认真实设备链路和数据质量，但不发布设定点、不改变模式、不解锁、不调用任务启动
服务。飞机应保持桨叶拆除或处于场地批准的等效安全状态。

观察内容：

- MID360 点云、IMU 频率和时间戳。
- FAST-LIO `/Odometry`、点云和 `camera_init -> body` 关系。
- MAVROS 连接、未解锁、落地、IMU、本地位置和时间同步状态。
- 外部视觉预览的方向、尺度、延迟和健康状态。
- 相机图像、内参和 AprilTag 检测稳定性。

`collect_readonly_flight_evidence.sh` 仅订阅已运行的节点，不会自行启动节点或发送命令。
`collect_frame_alignment_evidence.sh` 仅启动预览观察器，且必须在外部视觉输出关闭时使用。

### 第 4 级：地面联调

目标是在不自由飞行的条件下验证完整硬件、坐标方向和安全处置。必须由现场负责人制定
具体约束，例如拆桨、固定机架、限位系绳或单独测试投放机构。

至少完成：

- 机体各轴手动运动与 FAST-LIO/外部视觉方向一致。
- PX4 外部视觉融合配置、延迟和坐标约定经过验收。
- Offboard 设定点丢失后的 PX4 动作符合批准预案。
- 遥控接管、急停、断电和通信中断流程可执行。
- 舵机开关、机械限位、关闭回执和异常处置通过。
- 飞行前观察器在未解锁、落地状态给出一致结果。

### 第 5 级：受控实飞

目标是在封闭场地、明确安全边界和人工监督下逐步验证飞行能力。应从低高度短航段开始，
每次试验仅增加一项变量；禁止首次实飞直接运行完整竞赛任务。

进入本级前必须具备：

- 书面场地许可、人员分工、警戒范围和天气条件。
- 遥控手持续接管能力与口令明确的中止预案。
- 飞机结构、电池、桨叶、重心、载荷和投放机构检查。
- 第 1 至 4 级证据完成并由指导老师或安全负责人签字。
- 与冻结 Git SHA 对应的配置、PX4 参数和回退方案。

实飞证据应覆盖起飞、航点、对准、投放、返航、降落和失败处置。不得以未发生事故替代
接口、状态和精度证据。

## 验证状态矩阵

| 能力 | 源码检查通过 | 仿真验证 | 被动真机验证 | 尚未证明 |
| --- | --- | --- | --- | --- |
| Ubuntu/ROS 构建 | 有历史证据 | 不适用 | 有机载构建记录 | 所有目标硬件均可重复构建 |
| MID360 数据链路 | 配置和入口可检查 | 可模拟接口 | 点云与 IMU 曾被动出数 | 各参赛机长期稳定性 |
| FAST-LIO 定位 | 契约和配置可检查 | 桥接输入有覆盖 | `/Odometry` 曾稳定输出 | 完整场地精度和漂移上限 |
| MAVROS 连接 | 插件和 launch 可检查 | 服务与状态可模拟 | 被动连接、未解锁状态曾确认 | 全赛程通信可靠性 |
| 外部视觉转换 | 有单元与集成覆盖 | 正常和异常路径有覆盖 | 预览/链路可观察 | PX4 在全赛程正确融合 |
| 通用航点状态机 | 默认门禁可检查 | 闭环和故障注入有覆盖 | 只读输入可观察 | 完整实机路线 |
| C 组任务状态机 | 默认门禁可检查 | 航点、Tag、投放和异常有覆盖 | 感知链路可被动观察 | 当前赛道完整自主实飞 |
| 舵机串口 | 协议与接口可检查 | 命令和回执可模拟 | 设备可做地面检查 | 重复投放成功率和精度 |
| 当前规则适配 | 已发现历史参数差异 | 可验证修订后的流程 | 需现场核对 | 最终参数完全合规 |

“有历史证据”表示曾在特定版本和设备上观察到，不代表当前工作树、当前飞机或当前现场
直接继承该结论。复用前必须按当前 SHA 重新验证。

## 升级门槛

| 从 | 到 | 最低要求 |
| --- | --- | --- |
| 离线 | 仿真 | 构建和契约通过，仿真与实机完全隔离 |
| 仿真 | 只读实机 | 故障分支通过，设备清单和只读方案批准 |
| 只读实机 | 地面联调 | 数据频率、帧、时间同步和标定证据完整 |
| 地面联调 | 受控实飞 | PX4 保护、遥控接管、机械检查和现场方案批准 |
| 分段实飞 | 完整任务 | 每个独立航段、Tag、投放和降落均有可重复证据 |

## 证据最小集合

每份证据应包含：

- Git SHA、配置校验值和 PX4 参数快照。
- 验证等级、日期、场地、设备编号和人员角色。
- 启动入口、实际参数和 ROS 节点图。
- 状态、频率、时间戳、TF、消费者和错误日志。
- 视频或图片只作为补充，不替代结构化数据。
- 结论、未执行项、异常、清理结果和后续阶段批准人。

公开材料中应对地址、UID、人员信息和内部路径进行脱敏。

## 终止升级条件

- 文档、配置、PX4 参数和现场设备无法对应到同一版本。
- 视觉或本地位置帧不一致、时间戳异常或方向检查失败。
- 任何门禁需要通过修改代码、伪造状态或跳过标定才能通过。
- 失控保护、遥控接管或中止责任不明确。
- 场地出现无关人员、净空不足、天气或电池条件不合格。
- 最新规则尚未完成参数适配。
